# Quintで検証する性質

原文と訳文が同じページに属すること、完了済みの訳を再利用すること、ページ移動後に古い処理が表示を書き換えないことを、実行可能な状態機械として記述しています。開発環境の準備と一括実行コマンドは[ビルドとテスト](../docs/development.md#quintによる形式検証)にあります。

| 仕様 | モデル検査で確かめること | 対応する実装 |
| --- | --- | --- |
| [reader.qnt](reader.qnt) | 開く、パスワード要求、移動、検索、画像公開、抽出、OCR、翻訳、エラー、終了。画面に出せる本文・画像・訳文の出所とページ範囲。遅れて届く成功・失敗による上書きの防止 | [Reader、PDF・翻訳ワーカー、Shared::update](../crates/reader/src/session.rs) |
| [caches.qnt](caches.qnt) | 文書を開くと画像・本文キャッシュをクリアする。固定モデル・文体で原文が一致すれば文書間でも完成訳を再利用する。失敗、ヒット時の順序更新、件数・容量による追い出し、単体で上限を超える結果、セッションの破棄 | [pdf_loop、Cache、translate_loop](../crates/reader/src/session.rs) |
| [decode.qnt](decode.qnt) | モデル確認後のプロンプト処理、入力と生成の合計上限、途中キャンセル、異常終了。UTF-8の未完末尾や空白だけの結果を完成訳として公開しない | [Windowsのページ推論](../crates/plamo/src/page.rs)、[macOSのページ推論](../crates/reader/src/llama.rs)、[完成訳の受理](../crates/reader/src/session.rs) |
| [pool.qnt](pool.qnt) | 世代と幅を一緒に取得したワーカーだけが担当区画を実行する。幅が変わる連続ディスパッチ、遅れた非参加ワーカー、パニックを含め、参加者が一度ずつ完了してから呼び出し側がクロージャーを解放する | [Pool::dispatch と worker_loop](../crates/plamo/src/pool.rs) |
| [navigation.qnt](navigation.qnt) | 1始まりのページ境界、無効な操作でリビジョンを変えないこと、検索の折り返しと不一致、パスワード再入力、読み込み失敗、処理中の文書切り替え。既存のPDF fixtureから期待するページと本文を求める | [C ABI](../crates/reader/include/reader.h)、[スナップショット](../crates/reader/src/ffi.rs) |

### 探索の範囲

TLCはモデル内の到達状態を、操作列の長さを制限せず探索します。世代は「現行／失効」、画像や本文は出所を表す識別子、ハッシュは衝突しない原文の識別子に置き換えています。閲覧モデルは2文書・最大2ページと保留中の応答1件を扱います。キャッシュモデルは2文書・各4ページ、最大2件・容量3単位です。実装の上限はページキャッシュが8件・24 MiB、翻訳キャッシュが4,096件・256 MiBです。推論は容量5・出力上限3トークン、プールは呼び出し側1人とワーカー2人で、共有タスクを使う幅2と3を扱います。[Quint CLI のTLCバックエンド](https://quint.sh/docs/quint#using-tlc)

`readerProgress.finishesAfterLastRequest` は新しい閲覧要求が途絶えると処理が成功・失敗などの終端に達することを検査します。`pool.dispatchReturns` はディスパッチが呼び出し側へ戻ることを検査します。どちらも、実行可能なステップが継続すればいずれ実行されるという弱公平性を仮定します。OSや推論ライブラリ内の呼び出しが応答するまでの時間は扱いません。

推論の成功通知と画面への公開は別のステップです。`readerProgress.publishesSuccessfulTranslation` は後続の閲覧要求がない場合に、そのページの成功した訳が画面に届くことを検査します。`readableDocument.showsTranslation` では、PDFを正常に開いて読める原文が得られ、推論も成功する条件を与えます。この条件で成功応答を常にエラーにするワーカーや、成功応答を処理できないワーカーには、TLCが反例を返します。

### 実装との照合

一括検証ではQuintの設定済みシナリオと固定シードで生成したITF操作列を、ビルドした共有ライブラリに再生します。開く・移動・検索の各操作について、ページ、本文の目印、状態、画像、リビジョンを比較します。古いスナップショットの本文が読めること、既知の画像IDを渡すとPNGが省略されることも確認します。作業ディレクトリにfixtureを配置し、実行前後のファイル一覧・PDFの更新時刻・SHA-256を照合します。開発用の操作列とモデル検査器の出力先は `.work/quint/check-*` です。

| 境界条件 | 期待する結果と照合方法 |
| --- | --- |
| 最後の本文トークンで上限に達した | 次の候補がEOSで、訳文が空でなくUTF-8が完結していれば成功する。もう1つ本文トークンが必要なら上限エラーになる。S4実モデルのテストは余裕のあるコンテキストで本文トークン数を測り、ちょうど収まる場合と1つ足りない場合を比較する。[実モデルテスト](../crates/plamo/tests/page_limit.rs) |
| OCRが失敗した | 読める抽出文字があれば保持し、OCRの失敗を表示でき、元の文字から翻訳を続けられる。空のページでOCRが失敗した場合はエラーを伝える。[セッションテスト](../crates/reader/tests/session_contract.rs) |
| 検索で一致がなかった | 検索結果の通知でリビジョンが変わっても、画像ID・原文・訳文を保つ。C ABIの再生では検索中に観測したスナップショットにも適用する。WinUIでは画像IDの変化がスクロール位置・倍率のリセットを引き起こす。[C ABIの照合](../scripts/replay_quint.py) |
| 表示ページが単体でキャッシュ容量を超えた | そのページは表示でき、既存項目とその再利用順を保持する。Quintでは容量3単位のキャッシュを使い、Rustでは24 MiBを超える模擬画像を挟んで戻ったときの描画回数を測る。[キャッシュ仕様](caches.qnt) |

セッションテストは製品の `session.rs` をコンパイルし、PDF・OCR・推論の応答をテスト側から与えます。S4実モデルでの境界検査を一括実行に含めるには、`OPT_P4X86_TEST_MODEL` にモデルのパスを設定します。

翻訳の数値計算、OCRの認識精度、ネイティブの選択・コピー、OSや依存ライブラリによる全ファイルアクセスはモデルの抽象化の外にあります。読取専用コントロールは各OSのUIテストで、生成内容とキャッシュ再利用は同梱モデルを使うRustテストで確認します。[ネイティブテストの手順](../docs/development.md)

### 失敗を調べる

TLCの反例では違反に至る状態列を確認できます。形式仕様の検査が通るとC ABIとRustの照合に進み、いずれかで失敗すれば非ゼロ終了します。C ABIの照合失敗には再生したITFファイル名と操作番号が出ます。たとえば世代管理を変えた場合は `reader.qnt` の `lateTranslationTest` で、古い訳が届く前に別ページへ移動して同じページへ戻る順序を確認できます。同じ順序でRustの公開処理に古い成功・失敗を渡すテストと、実際の4,096件の境界でLRU順を照合するテストもあります。[Rust側の回帰テスト](../crates/reader/tests/session_contract.rs)
