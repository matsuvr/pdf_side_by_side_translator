# Embedded resources and diagnostics

The product embeds the Japanese help, complete notices and PNG icon as compiled
byte arrays. The Windows resource contains the private font, icon and version
information. The Mac bundle contains its private font and ICNS icon; its plist
identifies the product, Japanese development region, Retina support and minimum
deployment version. The original geometric icon is generated by the stdlib-only
`scripts/generate_icons.py`; no third-party art or font is used in the icon.

`scripts/collect_notices.py` collects 40 full license documents from the pinned
sources and recorded legal-text copies. It covers the actual PDFium GN closure
(including Chromium support, ICU, codecs, FreeType, HarfBuzz, Highway and the
private LLVM runtimes), wx core/base's image/regex dependencies, llama/ggml and
its linked hash helpers, SQLite and the Noto font. Dual-license choices are
identified. The two PLaMo contract texts are included for offline reference;
no weights, tokenizer implementation or model files are redistributed.
`deps/licenses.lock.json` records source paths and exact input/output hashes.
`--check` runs in CTest and fails on drift. FreeType's Latin-1 copyright text is
explicitly transcoded to Unicode without dropping its notice.

The model terms come from `LICENSE/ja` and `LICENSE/en` at the exact model
fixture revision. They are distinct from the application's MIT License.
The help explains separate model/output terms, the About dialog identifies
PLaMo, and exported text identifies the model, prose style and the condition
on models trained using generated output. Review the complete official terms
before model use; the application does not register users or accept a contract
on their behalf. The legal-text copies retain their original terms.

Only wx's PNG handler is registered. Registering every image codec pulls wx's
unprefixed IJG symbols into the executable and collides with PDFium's static
JPEG implementation. The product only decodes its embedded PNG through wx;
PDF image decoding belongs to PDFium. No duplicate-symbol suppression or
upstream patch is used.

Native Mac verification opened the diagnostic and license dialogs. Diagnostics
reported the loaded Metal backend, context 8192, eight threads, batch 512 and
micro-batch 128 from the live llama context. The long license document rendered
through the final PLaMo contract paragraph. Help/license dialogs open at their
beginning, support native selection/copy, and do not use a browser or network.

The structured diagnostic record cannot contain a free-form message, path,
password, source text or generated text. A bounded 64-record GUI summary and
I/O-thread log contain only code, backend, numeric configuration, page, outcome
and elapsed time. Optional log failure does not disable saving. Rotation retains
at most three 256-KiB generations; a regression verifies rotation and bounded
storage. Copying diagnostics displays the content first and sends nothing.

The state rescue action creates a self-contained SQLite backup on the I/O
thread, including settings, recent/reading state and pending source overrides
from an in-memory fallback. It excludes translation cache and does not change
the active storage destination. It refuses to replace files in active storage.
A regression restores the single backup file after an unwritable destination
and verifies settings and the pending source edit. To restore manually, close
the app, preserve its existing state directory (including WAL/SHM files), and
place the backup as `state.sqlite3` in a fresh state directory before launch.
The original future/corrupt state is never automatically deleted.

The 23 headless CTest checks pass on macOS arm64. Interactive long-text evidence
is in [native-text.md](native-text.md); other platform execution and final
distribution/clean-launch checks are tracked separately.
