# PLaMo 3 Translate 0.8B x86 S4（P4X86 v7）推論高速化レポート

Built with PLaMo.

## 結論
x86-64 CPU向けに、元のPFN BF16から独自の4bit量子化ファイルを作り直した。
旧P4X86 v2に対し、AVX2強制・2スレッドで翻訳処理時間24%短縮・生成速度20%向上、
4スレッドで処理時間31%短縮・生成速度43%向上を実測した。
公式GGUFを読み込む旧pure Rustエンジンとの比較でもそれぞれ29%・25%短縮。
今回の比較は同一Rustエンジン系列内の比較であり、llama.cpp本体との新規比較ではない。

モデルファイル: 516,613,376 bytes（約517 MB）、SHA256:
aa290f1609fc0ad49811060a8499a773ababd088b9d21dc3e907c287f4fe2478

## 何を変えたか
1. 元の32ウェイトごとのFP32スケール方式を改良。32ウェイトごとに最小二乗で
   スケールを選んだ後、256ウェイトの中の8スケールを整数7bit（1 byte）で表現し、
   ひとつのFP32共通スケールにまとめる。
2. 256ウェイト分を整数のまま積和する。FP32のスケール乗算回数を8分の1に減らし、
   AVX2のmaddubs/maddwd、FMAを活用。AVX-VNNI・AVX512-VNNIも自動選択。
   8行単位で事前配置し、バッチ入力間で展開済みウェイトを共有する。
3. 活性値のINT8量子化をAVX2でベクトル化。旧v2モデルでも、SIMD/FMAカーネルの
   改善だけで高速化できる。埋め込み、出力語彙層、3072語の動的候補選択は維持。
   実際の生成速度向上は候補数をさらに削った結果ではない。
4. 各行の256ウェイトは140 bytes（4.375 bits/weight）。層の重みは349,962,240
   bytesから306,216,960 bytesへ約12.5%減少。モデル全体は560 MBから517 MBへ。

## 実測（AVX2強制）
AMD EPYC 9V74、Linux x86-64クラウド。tasksetで2/4仮想CPUに固定した。
英語3文、中国語2文、フランス語1文を日本語に翻訳。context=4096、最大128生成、
投機生成を無効化。6文の総処理時間はprefill・decodeを含む。
旧エンジン（前回納品時の実行ファイル）、新エンジン+旧v2、同+v7、
旧エンジン+公式Q4_K_M GGUFを順送り/逆送りで各2プロセス、各3回測定。
中央値6試行。モデル開く時間は2プロセスの中央値。OSキャッシュ状態は制御せず、
各プロセスの第2/3試行では固定PFMLプレフィックス再利用。
プロファイリングは新エンジンのみ（マトリクス時間の時計計測）。
6件の出力トークン数はv2とv7で一致（106トークン）、GGUFは107トークン。
v2とv7の訳文は3件が文字単位で一致、残る3件は同義表現の差。

モデル推論の実測値はハードウェア・仮想CPUのスケジューリング・データに依存する。
強制AVX2は実機N100等の性能を再現するものではなく、AVX512系を無効化した同一CPU比較。

自動選択（AVX512-VNNI対応ホスト、各3回の中央値）:
| スレッド | 新エンジン＋v2 総秒 / tok/s | 新エンジン＋v7 総秒 / tok/s |
|---:|---:|---:|
|2|2.557 / 55.874|2.201 / 88.771|
|4|1.878 / 71.583|1.922 / 88.061|

4スレッド自動選択では生成速度が高くなった一方、総時間はほぼ同程度。
AVX-VNNIはコンパイル検証、同機能を持つIntel実機は今後の確認対象。

## 後半のボトルネック
v7の生成1トークンあたり実際に参照する層の重みは306.2 MB。
出力候補の再評価と1bit索引を概算で加えると約332 MB（埋め込み全行は読まない）。
90.4 tok/sは概算30 GB/sの読み出し相当。別途384 MiBの配列をSIMDで走査すると
同ホストで2スレッド43.2 GB/s、4スレッド35.5 GB/s（中央値、別測定）。
この概算では、特に4スレッド生成速度はメモリ帯域の制約に近づいている。
CPUキャッシュや実際のワークロードによる異同があるため、厳密な上限ではない。
プロファイルでは、v7の4スレッドマトリクス単発計算約0.97秒、バッチ約0.56秒、
出力層約0.12秒が6文の大半を占める。さらなる改善は重み帯域とバッチGEMMが中心。

## 翻訳品質と検証
18文の追加技術系テスト（英語、中国語簡体・繁体、韓国語、仏語、独語、西語、露語、
日→英、日→中、中→英）を実際に翻訳。v2とv7のうち11文は文字単位で一致。
18文とも正常停止し、目視比較では重要な数値・日時・否定・条件が維持された。
表現差の例: 中国語「新的治疗方案」をv2「新たな治療レジメン」、
v7「新たな治療プログラム」と表現。小規模検証であり53言語の統計的な同等性は別途必要。
生出力はquality-v2.tsv、quality-v7.tsv、quality-gguf.tsv。

単体テスト13件をAVX2強制および自動選択で成功。S4行形式とタイル形式の
同一量子値の内積、スカラーとの一致、FMA/VNNIの実行可能CPU上の一致を確認。
Windows MSVC x86-64のcargo checkはCLI、変換器、ベンチ・品質プローブで成功。
Linuxで全語彙評価（--exact）の短い英日翻訳も正常終了。

## 比較したが採用しなかった案
- v3: row-major W4・group64。容量減と生成速度には効果があったがprefillが遅くなった。
- v4: 変換時にW7/A8のprefill用行列を追加した混合精度（約1.09 GB）。
  重み量とメモリ読み出しが増え、今回の短文タスクは遅くなった。
- v5: FFNだけ3bit。容量469 MB級まで削ったが、AVX2の3bit展開が重く、
  特に2スレッドで速度が劣った。
- v6: v7と同じ量子化を行形式で保存。実行時のSIMD並列化・prefillを考え、
  8行タイル配置のv7を採用。
